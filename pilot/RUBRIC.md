# Rubrics and report format — frozen (v2, post-review)

Revised after Codex's review of the first freeze (board ids 27 + 29):
strict whole-output grading, E split into citation vs blind-graded
factual, raw-record integrity, R reported by view. Implemented in
score_pilot.py; regression-covered by test_score_pilot.py.

## Integrity (checked before any scoring)

Exactly one raw record per frozen (item, arm) — 34 × 2 = 68 records.
A duplicate or missing record aborts scoring (exit 2) and is reported
as a run blocker, never silently scored around.

## Per-task scoring

### R — Read (strict)
The ENTIRE raw output must parse as exactly one JSON object
(`not_single_json` otherwise). **Correct** iff that object deep-equals
the item's expected facts (vlan-id keys normalized to strings;
`trunk_allowed` compared as a set). Failure classes: `not_single_json`,
`unparseable`, `facts_mismatch`. First-object extraction grading is
kept as a clearly-labeled diagnostic in the report — it is never the
score (a correct first object followed by a conflicting second object
must not pass).

### P — Predict / Edit (strict)
Same whole-output parse rule. The object is the model output in the
engine's own shapes: a plan (`{"device", "operation", ...}` or
`{"device", "steps": [...]}`), a clarify (`{"type": "clarify", ...}`),
or the pilot-surface no-op (`{"type": "no_op"}`).
- Shape enforcement: a no_op output must be exactly `{"type": "no_op"}`
  (`shape_error` otherwise). Clarify and plan shapes go through the
  engine's `validate_output()` — which requires the clarify `question`
  and list-of-strings `candidates`, and all plan field types
  (`validation_error` otherwise).
- Plan items: `apply_plan()` must apply cleanly; every golden
  assertion must hold after apply; `diff_states()` must show no
  changed path outside the asserted set (preservation is graded).
  Failure classes: `not_single_json`, `unparseable`, `shape_error`,
  `wrong_kind`, `validation_error`, `assertion_failed`,
  `preservation_violation`.
- no_op items: correct iff the output is the exact no_op shape, or a
  plan whose apply changes nothing.
- clarify items: correct iff the (validated) clarify object's reason
  matches exactly and its candidate set matches exactly
  (order-insensitive). Failure class: `clarify_mismatch`.

### E — Explain (split: citation mechanical, factual blind)
- **Citation accuracy** (mechanical): the final `Citation:` line equals
  the item's expected citation (module + path, whitespace/case
  normalized). Failure classes: `citation_missing`,
  `citation_mismatch`.
- **Factual correctness** (blind rubric): graded from
  `results/blind_e_sheet.jsonl` — arm labels stripped, order shuffled —
  against `e_rubric.md`'s per-item requirements, by a grader who does
  not know which arm produced which answer. An answer that negates its
  required facts is incorrect no matter how many right words it
  contains.
- **Keyword coverage is a diagnostic only.** It cannot distinguish an
  answer from its negation, so it is reported for transparency and
  never counts as correctness.

## Report format (results/RESULTS.md, generated by the scorer)

- R and P: one table per task, rows per (arm, view) with denominators
  and strict accuracy; below each, paired outcomes per arm (both views
  correct / one / neither, of the view pairs) and the extraction
  diagnostic per arm, labeled as not-the-score.
- E: one row per arm — citation correct / items, keyword diagnostic
  (labeled), and factual correct / graded (or "pending blind grading").
- Failure-class counts (strict, R/P) below the tables.
- No pooled "overall accuracy" headline number. Per-item records land
  in `results/scores.json`; `results/raw_outputs.jsonl` preserves
  every raw generation with its prompt hash and token/finish metadata,
  so any number traces to the exact prompt and output behind it.

Paired outcomes are the reading-vs-deciding diagnostic: JSON-right /
CLI-wrong indicates a reading problem; both-wrong a decision problem.
